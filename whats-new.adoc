[[backup-and-recovery]]
=== Backup and Recovery



==== Kubernetes-Workloads-Erweiterungen

In dieser Version führt NetApp Backup and Recovery die folgenden Verbesserungen für Kubernetes-Workloads ein:

* *Trident Protect 26.10*: Diese Version enthält Trident Protect 26.10.
* *Unterstützung für ontap-nas-economy- und ontap-san-economy-Treiber*: Sie können jetzt Persistent Volume Claims (PVCs) schützen, die über den NetApp Trident `ontap-nas-economy`-Treiber (Qtrees) und den `ontap-san-economy`-Treiber (LUNs) bereitgestellt werden. Wenn Sie PVCs mithilfe von Economy-Treibern schützen, wird das gesamte zugrunde liegende FlexVol oder die LUN geschützt. Sie können einzelne PVCs aus diesen Backups wiederherstellen.
* *Kubernetes fähige Warnmeldungen*: Warnmeldungen werden jetzt pro Kubernetes Applikation statt pro Volume nur noch einmal gesendet.
* *Unterstützung für Volume-Group-Snapshots*: Sie können jetzt Volume Groups erstellen, wenn Sie eine Kubernetes-Applikation definieren. Volume Groups ermöglichen es Ihnen, Snapshots von mehreren Volumes gemeinsam als absturzkonsistente Gruppe zu erstellen, wodurch die Datenkonsistenz über alle Volumes in der Gruppe hinweg sichergestellt wird.
* *Unterstützung für S3-kompatiblen Objektspeicher*: Sie können jetzt Kubernetes-Applikationsressourcen und -daten auf S3-kompatiblem Objektspeicher sichern, indem Sie Anmeldedaten für Sicherungsziele hinzufügen und Sicherungsrichtlinien konfigurieren.


Weitere Informationen zum Schutz von Kubernetes-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Informationen zum Schutz von Kubernetes Workloads mit NetApp Backup and Recovery"^].



==== ONTAP Volumes Workloads-Verbesserungen

In dieser Version führt NetApp Backup and Recovery die folgenden Verbesserungen für ONTAP Volumes Workloads ein:

* *Sicherungsberichte*: NetApp Backup and Recovery unterstützt jetzt das Erstellen und Herunterladen erweiterter Berichte für Workloads von ONTAP Volumes.
* *Backups beim Abmelden eines ONTAP Systems beibehalten*: Wenn Sie ein ONTAP System von NetApp Backup and Recovery abmelden, können Sie nun auswählen, ob Sie die zuvor gesicherten Daten verwerfen oder für eine Wiederherstellung verfügbar halten möchten. Die Dokumentation zu NetApp Backup and Recovery enthält nun Anweisungen zur Verwendung der ONTAP CLI zur Wiederherstellung der beibehaltenen Daten nach dem Abmelden des Systems.


Weitere Einzelheiten finden sich unter https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["Aufhebung der Registrierung von Backup and Recovery für ein System"^].

Weitere Informationen zum Schutz von ONTAP Volumes-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Informationen zum ONTAP Volumeschutz mit NetApp Backup und Recovery"^].



==== Erweiterung der Oracle Database Workloads

In dieser Version führt NetApp Backup and Recovery die folgende Verbesserung für Oracle Database Workloads ein:

*Wiederherstellung an einem alternativen Speicherort*: NetApp Backup and Recovery unterstützt jetzt die Wiederherstellung einer Oracle-Datenbank an einem alternativen Speicherort (einem anderen registrierten Host).

Weitere Informationen zum Schutz von Oracle Database-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Informationen zum Schutz von Oracle Database Workloads mit NetApp Backup and Recovery"^].

[[backup-and-recovery]]
=== Backup and Recovery



==== Allgemeine NetApp Backup and Recovery-Verbesserung

In dieser Version führt NetApp Backup and Recovery die folgende Lizenzierungserweiterung für alle Workloads ein:

*Lizenzänderung*: Für Backups mit Disk-to-Disk- oder Disk-to-Disk-Fan-Out-Architekturen fallen keine Gebühren mehr an. Gebühren fallen nur für Backups auf Objekt-Storage an, einschließlich Backups mit 3-2-1- oder Disk-to-Object-Storage-Architekturen.

Weitere Informationen zur Lizenzierung finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["Einrichtung der Lizenzierung für NetApp Backup and Recovery"].



==== Hyper-V-Workload-Verbesserungen

In dieser Version werden für Hyper-V-Workloads die folgenden Verbesserungen eingeführt:

* *NetApp MetroCluster support*: NetApp Backup and Recovery ermöglicht es Ihnen jetzt, Hyper-V-VMs zu schützen, die von NetApp MetroCluster gespiegelt werden.
* *Datenträgerübergreifender Schutz für SAN-VMs*: Bei CIFS- und SAN-Konfigurationen können Sie jetzt alle an jede VM in einer Schutzgruppe angeschlossenen Datenträger schützen. Dies umfasst Dateien, die über mehrere ONTAP Volumes oder ONTAP Storage Systeme verteilt sind (datenträgerübergreifende Datenträger), sowie Dateien, die auf einen einzelnen Speicherort beschränkt sind.


Weitere Informationen zum Schutz von Hyper-V-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-hyperv-protect-overview.html["Informationen zum Schutz von Hyper-V Workloads mit NetApp Backup and Recovery"].



==== Erweiterung der Oracle Database Workloads

In dieser Version wird für Oracle Database-Workloads die folgende Verbesserung eingeführt:

*Automatische Archivprotokollverwaltung*: Bei Vorgängen zur Datenbankwiederherstellung und zum Klonen erkennt und mountet NetApp Backup and Recovery die erforderlichen Archivprotokolle automatisch und hängt sie nach Abschluss des Vorgangs wieder aus. Primäre, sekundäre und Objekt-Storage-Protokollquellen werden unterstützt.

Weitere Informationen zum Schutz von Oracle Database-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Informationen zum Schutz von Oracle Database Workloads mit NetApp Backup and Recovery"].

==== ONTAP Volumes Workloads-Verbesserungen

In dieser Version führt ONTAP Volumes Workloads die folgenden Vorschauverbesserungen ein:

* *Verbesserte Unterstützung für Dark Sites*: NetApp Backup and Recovery for dark sites bietet jetzt dieselben ONTAP Volumes Datenschutzfunktionen wie NetApp Backup and Recovery. Diese Verbesserung umfasst aktualisierte Backup-, Wiederherstellungs- und Job-Management-Services sowie eine neue Metadaten-Datenbank. Während eines Upgrades bleiben vorhandene Datenbankdaten erhalten und werden automatisch migriert. Nach dem Upgrade ist eine Überprüfung der Audit-Protokolle erforderlich, um sicherzustellen, dass die Migration erfolgreich abgeschlossen wurde. NetApp Backup and Recovery for dark sites unterstützt nur ONTAP Volumes Workloads.
* *Abbrechen von Volume-Wiederherstellungsaufträgen*: Laufende ONTAP Volumes-Wiederherstellungsaufträge können jetzt auf der Seite zur Auftragsüberwachung abgebrochen werden, was die Verwaltung lang laufender oder langsam ausgeführter Aufträge vereinfacht.
* *Verbesserte Statusberichterstattung zur Volume-Indizierung*: Das ONTAP Volumes Dashboard meldet den Indizierungsstatus jetzt genauer, indem der  `Not Applicable`Status für Volumes und Snapshot-Kopien eingeführt wird, die nicht für die Indizierung geeignet sind. Der  `Not Indexed`Status ist jetzt Volumes vorbehalten, die auf die Indizierung warten, und die Volume-Details zeigen jetzt den Indizierungsstatus pro Snapshot mit einem Hovertext an, der erklärt, warum ein Volume oder eine Snapshot-Kopie nicht indiziert wird.
* *NetApp AFX Unterstützung*: Sie können jetzt Volumes schützen, die auf 2- und 4-Knoten-NetApp AFX Clustern gehostet werden.


Weitere Informationen zum Schutz von ONTAP Volumes-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Informationen zum ONTAP Volumeschutz mit NetApp Backup und Recovery"].



==== Kubernetes-Workloads-Erweiterungen

In dieser Version werden für Kubernetes-Workloads die folgenden Verbesserungen eingeführt:

* *Trident Protect 26.09*: Diese Version enthält Trident Protect 26.09.
* *Cluster- und Namespace-granulare rollenbasierte Zugriffskontrolle (RBAC)*: Bei der Kubernetes Cluster-Erkennung kann der Zugriff auf Ressourcen durch die Auswahl eines Projekts oder Ordners gesteuert werden, das bzw. der dem neuen Cluster zugeordnet wird. Außerdem können bestimmte Namespaces für die Zugriffskontrolle registriert werden. Dadurch wird eine granularere Zugriffskontrolle entweder auf Cluster- oder Namespace-Ebene ermöglicht.
* *Dateien und Ordner wiederherstellen*: Es ist jetzt möglich, bestimmte Dateien und Ordner aus Kubernetes VM-basierten Anwendungssicherungen wiederherzustellen oder herunterzuladen.


Weitere Informationen zum Schutz von Kubernetes-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Informationen zum Schutz von Kubernetes Workloads mit NetApp Backup and Recovery"].

==== Kubernetes-Workloads-Erweiterungen

In dieser Version werden für Kubernetes-Workloads die folgenden Verbesserungen eingeführt:

* *Trident Protect 26.08*: Diese Version enthält Trident Protect 26.08.
* *Backup-Wiederholungsversuche*: Backup-Wiederholungsversuche können jetzt aktiviert und die Anzahl der Wiederholungsversuche sowie die Intervalle zwischen den Wiederholungsversuchen als erweiterte Einstellungen in Kubernetes-Schutzrichtlinien konfiguriert werden.
* *Teilweise erfolgreiche Sicherung*: Es besteht jetzt die Möglichkeit, in den Kubernetes-Schutzrichtlinien erweiterte Einstellungen zu konfigurieren, damit die Sicherung auch bei Ausfall einzelner Ressourcen fortgesetzt wird und Sicherungsaufträge als teilweise erfolgreich abgeschlossen werden können. Dadurch ist die Wiederherstellung gesicherter Ressourcen möglich, selbst wenn während des Sicherungsvorgangs einige Ressourcen ausfallen.
* *Absturzkonsistente und VM-konsistente Backups*: Der Backup and Recovery Dienst für NetApp Console unterstützt jetzt die Konfiguration von Schutzrichtlinien, die absturzkonsistente oder VM-konsistente Backups oder Snapshots erstellen. Es besteht zudem die Möglichkeit, anzupassen, wie VM-Einfrierungen während des Schutzvorgangs durchgeführt werden.
* *Wiederverbindung des Kubernetes-Clusters bei Änderung der Console-Agent-IP-Adresse*: Der Backup- und Wiederherstellungsdienst für NetApp Console ermöglicht jetzt die erneute Verbindung eines Clusters mit seinem Console-Agenten, wenn sich die IP-Adresse des Agenten ändert.
* *Cluster auf neuen Console Agent migrieren*: Der Backup and Recovery Dienst für NetApp Console ermöglicht jetzt die Migration eines Clusters auf einen neuen Console Agent, falls der ursprüngliche Agent ausfällt oder gelöscht wird, wodurch ein unterbrechungsfreier Anwendungsschutz sichergestellt wird.


Weitere Informationen zum Schutz von Kubernetes-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Informationen zum Schutz von Kubernetes Workloads mit NetApp Backup and Recovery"].

* *Wiederherstellung von Pluggable Databases (PDBs)*: Es ist jetzt möglich, einzelne Pluggable Databases (PDBs) und PDB-Tablespaces wiederherzustellen, einschließlich zeitpunktgenauer Wiederherstellung.
* *Pluggable Database (PDB) Klonen*: Es ist jetzt möglich, eine einzelne PDB in eine bestehende Ziel-Containerdatenbank (CDB) zu klonen und optional PDBs auszuschließen, wenn eine komplette Containerdatenbank geklont wird.


Weitere Informationen zum Schutz von Oracle Database-Workloads finden Sie unter  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Informationen zum Schutz von Oracle Database Workloads mit NetApp Backup and Recovery"].
